# 资源预约领域设计

资源代表一组设备，时段是 UTC 半开区间 [开始, 结束)，每笔预约占用一个名额。相邻时段允许；同一资源的重叠创建由资源行锁保护。只允许预约未开始的开放时段。管理员关闭尚有占用的资源或时段会被拒绝。

| 数据表 | 含义 |
| --- | --- |
| resources、resource_slots | 资源、起止时间、容量、占用、版本 |
| campus_users | 账号、BCrypt 密码哈希、角色 |
| reservation_orders | 确认和取消历史；有效用户生成列唯一限制同一时段的重复订单 |
| waitlist_entries | 入队顺序、限时 OFFERED、接受的订单、过期或退出状态 |
| booking_requests | 异步请求编号、发起用户、目标时段和处理结果 |
| booking_outbox | 与请求一起提交的待发送记录、发送租约和确认时间 |

## 事务和容量

同步预约读取时段快照，用版本条件更新暂定占用。版本冲突在新事务中最多重试三次，再用时段行锁处理。更新成功后持有行锁，检查当前状态和重复记录，插入订单；检查失败时暂定更新回滚。取消、候补、超时和异步消费者按同一时段串行处理。数据库 CHECK 保证占用范围，唯一索引为重复订单提供第二道保护；已取消记录的生成列为 NULL，不阻止再次预约。

占用 = 已确认订单数 + 尚保留的候补 offer 数。取消把订单改为 CANCELLED，再为最早的等待者留出名额；确认只把 offer 转成订单，不再增加占用。过期或退出释放名额再递补。超过时段开始时间的订单保留历史，未确认的候补结束。所有这些状态转换和容量变动都在同一个数据库事务中。

## Redis

查询缓存按资源隔离，保存 5 秒，业务事务提交后删除。并发读回填或缓存不可用时，查询可能短暂读到旧快照或回源；预约不依赖缓存结果。Lua 使用同槽键，在一个操作中清理过期项、检查用户在途令牌、检查并分配入口额度。额度来自数据库可用量快照，限制在 1–128；即使数据库瞬时满额也允许一次尝试交给数据库确认。请求结束用同一个令牌释放，异常遗留最多保留 120 秒。缓存或入口不可用时回到 MySQL 校验；Lua 降低在途竞争，不承担最终库存，也不承诺在所有负载下更快。

## RabbitMQ

受理事务提交请求和发件表，随后独立任务领取待发送记录。等待 broker confirm，同时检查 unroutable return；无确认时保留并稍后重投。处理租约到期可重新领取，因此可能重复发布。消费者先锁时段、再锁请求，若已终结则直接确认；成功时订单、名额和请求状态一起提交，提交完成才 ACK。业务拒绝记录 REJECTED，无需重试。技术错误经延迟队列最多处理三次，再进入死信。数据库故障阻止及时写终态时，恢复后由截止时间任务结清。发布端的重投带有上限退避，最晚到达请求的处理截止时间。

不提供跨系统 exactly-once。重复投递由持久化状态、事务和唯一约束约束业务效果；MQ 已接收也不等同于用户预约成功。
